# 视频平台需求汇总与验收清单

整理日期：2026-11-05（Asia/Manila）  
来源：本次对话中的文字要求、截图、视频参考及后续纠正。

> 本文记录用户要达到的效果，不等于功能已经验收通过。以最后一次明确要求为准；有冲突且尚未明确的内容单独列出。提交代码、构建通过、模拟浏览器测试通过，均不能代替线上及 iPhone 真机验收。

## 1. 项目目标和范围

平台包括用户网站、管理后台和 EFV 云转码对接。用户网站提供群聊、私聊、短视频、长视频和个人中心；管理员维护群组、分类和内容；上传的视频提交至 EFV 转码，再同步到本站展示和播放。

- 前端整体参考快手的内容展示和紧凑布局。
- 聊天参考 Telegram 的会话列表、消息气泡和手机交互。
- 普通页面采用白色、浅色风格；视频播放页面采用黑色。
- 前台移除直播入口；原“命理”入口改为长视频。
- 群组由后台创建维护，本次不开放前台用户自建群。
- 本次不要求制作原生 App，也不因参考图出现联系人、通话按钮就新增这些功能。

## 2. 最终要求速查

| 范围 | 最终要求 |
| --- | --- |
| 普通页面 | 白色背景，不受播放页黑色主题影响 |
| 播放页面 | 顶部系统状态栏背景期望为黑色，播放器黑底；返回按钮叠在视频上，不额外填充黑色标题条 |
| 主导航 | 从左到右：群聊、短视频、中央加号、长视频、我 |
| 聊天详情 | 不显示主导航；右滑返回会话列表，沿用原体验 |
| 短视频分类 | 左右滑动切换分类，沿用原体验 |
| 其他页面 | 不需要横向切页；特别要阻止从屏幕边缘滑回旧播放页 |
| 封面 | 使用清晰的 EFV 封面；宽度固定，高度按图片比例自适应 |
| 预加载 | 提前准备首屏 6 张封面；进入短视频、切分类尽量无闪烁 |
| 批量上传 | 最多 100 个文件，可分批选择；单个视频上限 5 GB |
| 上传结果 | 本站短视频表必须有记录；转码完成后自动补齐播放地址、封面、时长等并按发布规则展示 |
| 数据同步 | 同步新增、修改和远端删除；分页不完整时不能误下架 |
| 长时间使用 | 不应出现按钮失效、明显迟缓、拖动状态卡住或消息同步堆积 |

## 3. 页面布局和主导航

### UI-01 普通页面视觉

- 按最新快手参考图采用浅色内容界面，不能继续沿用最初的全站深色方案。
- 视频发现页展示双列瀑布流；卡片含封面、作者头像/名称、点赞数，必要时展示标题。
- 封面列宽固定，高度随图片比例变化；不要把所有封面强制裁成扁横图。
- 卡片间保留细小间隙，分类拖动和切换动画中也不能消失。
- 桌面端需要适应屏幕宽度，不能直接照搬手机截图尺寸。

### UI-02 底部主导航

- 保留五个位置：**群聊｜短视频｜＋｜长视频｜我**。
- 对应参考图的替换关系：原“首页”改为“群聊”，“精选”改为“短视频”，“消息”改为“长视频”。
- 字体应清晰、足够大；中央加号较普通文字略突出。
- 压缩导航上下留白，避免浪费屏幕空间；不能为了缩小导航把文字也缩得过小。
- 聊天详情隐藏该导航，回到聊天列表后恢复。

### UI-03 视口和输入适配

- 页面固定在可见视口内，内容区域内部纵向滚动。
- 限制移动端双指、双击导致的页面放大，防止横向溢出和页面错位。
- 键盘弹起后消息输入框和聊天内容应正常布局，不应出现整块黑色空白或内容被挤到屏幕外。
- 截图中的 Safari 地址栏、系统键盘附件栏属于浏览器/系统界面，应与网页自绘内容区分；不能把改背景颜色称为删除了系统控件。

## 4. 群聊与私聊

### CHAT-01 会话列表

- Telegram 式列表：圆形头像、会话名、最新消息摘要、时间、未读数。
- 支持“所有聊天、群组、私聊”筛选，支持切换多个后台维护的群。
- 保留搜索框；去掉左上角“搜索”文字按钮，在其位置展示实时连接状态。
- 不再在列表底部额外占一行展示重复的连接状态。
- 去掉“聊天”标题旁的飞机图标。
- 压缩列表行上下间距；头像保持固定尺寸、圆形裁切，不能按原图高度撑开列表。
- 查看群历史再返回列表时，不保留蓝色选中底色或其他异常变色。
- 后台更换群头像后，前端能正确显示最新图片。

### CHAT-02 聊天详情与返回

- 显示会话头像、名称、消息气泡和时间；发送方与接收方有清晰区分。
- 手机在会话列表和聊天详情之间切换；电脑可以使用双栏。
- 聊天详情不显示底部主导航。
- 从左向右拖动返回会话列表：页面跟手移动，露出下层列表；距离足够松手返回，不足则弹回。
- 动画参考 Telegram/快手，应平滑，不僵硬，不出现空白或突跳。
- **最新补充：这项已有手势不需要继续改动，不要为拦截其他页面而重写它。**

### CHAT-03 私聊、消息与历史

- 从群成员或群消息发送者入口发起私聊。
- 私聊仅双方可访问，不能被第三方读取或发送消息。
- 新消息实时显示，不需要刷新页面。
- 切换群组不串消息；历史记录分页加载，向上翻页时保持阅读位置。
- 断线重连后补齐遗漏消息，避免重复、丢失和乱序。
- 前台不开放用户自建群。

## 5. 手势边界和长时间停留

### GESTURE-01 允许的横向交互

仅保留已有的两种页面内交互：

1. 聊天详情右滑返回会话列表。
2. 短视频左右滑动切换小分类。

其他页面不需要左右滑动切换页面。纵向滚动、正常点击、输入和分类条自身的浏览不能因此失效。

### GESTURE-02 屏幕边缘与旧播放页

- 最左边和最右边也需要纳入测试，不能只拦截页面中央的拖动。
- 从群聊或其他页面横滑，不应进入旧短视频播放页。
- 离开播放器后，不应因历史前进恢复已关闭的播放会话，继而读取过期数据或显示“获取播放地址失败”。
- 区分应用自定义滑动与 Safari 原生历史返回/前进；浏览器历史造成的问题不能只通过修改卡片动画处理。
- 不采用不断增加历史记录来困住用户的方案。

### PERF-01 长时间停留

- 长时间停留、切后台再回来、锁屏再解锁后，主导航和操作按钮应能及时响应。
- 网络恢复后可继续切群、发消息、切分类和播放。
- 同步任务不应无限重叠，消息缓存和渲染数量不应因持续收消息而无限增长。
- 手势取消、切页、页面恢复后，不应残留遮挡点击的层或无法退出的拖动状态。
- 若无法立即恢复，应提供明确失败提示和重试入口，不能长时间无反馈。

## 6. 短视频发现、封面和预加载

### VIDEO-01 分类和列表

- 支持“全部”及后台维护的小分类，例如“国产、精选”。
- 分类图标/头像需要显示；不能把恢复图标误解为新增其他入口。
- 分类图和视频封面是不同数据：分类图用于分类入口，视频封面用于视频卡片。
- 列表保持双列瀑布流：固定列宽、图片按比例自适应高度。

### VIDEO-02 提前加载

- 不要等用户滑到列表底部才加载下一批，需要更早预取。
- 每批列表数据加载后，提前准备至少前 6 张视频封面。
- 从群聊切到短视频时，希望首屏封面已准备好，而不是进入后先闪一下占位图。
- 切换“全部、国产、精选”等小分类也采用相同策略。
- 往返切换分类应无缝衔接，不先清空列表、不闪灰块、不展示旧分类混入的新内容。
- 预加载失败不能永久锁住分类切换或所有操作。

### VIDEO-03 EFV 封面质量与更新

- 优先使用 EFV 提供的清晰封面/截图数据，不用低清、小尺寸转存图替代高清原图。
- 后台修改封面后，本站后台和前台都应同步更新；缓存不能长期显示旧封面。
- 图片上传成功不等于展示成功：前端实际请求必须能访问，并正确处理路径、HTTPS 和加密。
- 可以使用浏览器 Blob URL 展示解密后的图片；Blob URL 是运行时地址，不作为永久媒体地址保存。
- 加密图片需按 EFV 文档对接，不能把加密文件直接当普通 JPEG/WebP 展示。

## 7. 视频播放与系统状态栏

### PLAYER-01 播放控制与稳定性

- 提供明确的播放/暂停按钮、播放进度和当前时间/总时长。
- 支持拖动进度条；加载、暂停、播放失败应有可辨认状态和重试入口。
- 点视频进入时不先跳蓝屏；上下切视频时不闪屏。
- 进入播放页时先显示所点击视频的封面，首帧准备好后再显示视频；等待过程不能只有黑色空画面。
- 最新要求：iPhone 使用独立加载的黑色播放文档；HTML 加载阶段先显示已点击的封面，播放器封面或首帧就绪后交接。其他设备保留站内覆盖层。
- 缓冲后应能继续播放，不能无提示停在封面或始终为 00:00。
- 横向视频不能被当成竖向视频强行处理。
- 防盗链打开后，本站应通过正确的鉴权/播放链路播放，不应继续请求被拒绝的裸 M3U8。

### PLAYER-04 返回、预加载和前后台恢复

- 播放页面从左边缘向右拖动，页面跟随手指，露出底下的当前分类列表；达到距离或速度阈值后返回，不足时回弹。
- 点击返回和右滑返回均恢复原分类、原滚动位置。iPhone 跨文档时从会话快照恢复，不重新拉取当前列表；其他设备保留列表 DOM。
- 播放期间预取当前视频附近 6 张封面，分类不足 6 条时只加载实际存在的内容。
- 切到其他 App 后暂停播放器加载与计时任务；回来优先复用当前媒体并恢复进度，地址失效时重新获取。用户手动暂停的内容不自动播放。
- 仅挂载当前视频附近的封面和交互区，避免长列表持续增加解码和 DOM 开销；上下切换不闪屏。

### PLAYER-02 尺寸要求及待明确边界

尺寸要求有多次调整，需要保留先后关系：

| 阶段 | 用户要求 | 当前解释 |
| --- | --- | --- |
| 较早 | 原始比例、居中，空白黑色填充，不刻意铺满 | 后续又补充宽度铺满，不能忽略后续要求 |
| 后续 | 宽度适应屏幕，高度不足拉伸 | 随后又明确不做拉伸，因此不作为最终的纵向拉伸规则 |
| 再后续 | 视频不做拉伸，居中 | 保留居中和不强制纵向拉伸的方向 |
| 最后明确的尺寸补充 | “宽度全部拉满，铺满整个屏幕，高度不变” | 宽度占满；不要为了填满屏幕额外增加高度 |

待明确：对于原始比例与“宽度铺满、高度不变”无法同时满足的素材，允许横向变形还是应按原比例留黑边。不能自行把“高度不变”再次改成纵向铺满。本项与状态栏颜色修改分开验收。

### PLAYER-03 最终颜色范围

- **普通页面白色 → 视频播放时黑色 → 退出恢复白色。**
- 用户所指重点是 iPhone 顶部时间、信号、电量所在的系统状态栏背景。
- 播放器空白区域采用黑色。
- 返回按钮在视频画面上，不为按钮另留一条黑色标题区或大块占位。
- 不能将全站背景改黑，以替代“仅播放时黑色”的要求。
- 重点环境：**iOS 26、Safari 无痕标签页**。
- 真机多次反馈仍为白色，因此本项不得仅凭网页 DOM 背景为黑就标记验收通过。
- 站内播放外壳采用贴住视口的固定、不透明黑底，不随右滑变换；右滑中的播放器移动时暂时透明以露出列表。不通过新增标题条填黑。iPhone 14 Pro Max 等用户设备仍须真机验收。
- iPhone 独立播放文档从初始 HTML 即为黑底，普通文档从初始 HTML 即为白底；Safari 系统状态栏颜色仍须单独真机验证。

## 8. 管理后台与批量上传

### ADMIN-01 后台可用性

- 登录、用户列表、分类切换和 Livewire 操作不应出现 500、白屏或 HTTP/2 响应中断。
- HTTPS 页面资源全部使用 HTTPS，避免 CSS/JS 被 Mixed Content 阻止。
- 后台上传的封面和头像能在后台预览，并在前端正常显示。
- 普通会员与后台管理员的身份、列表和权限应清晰区分；不能因为昵称是“管理员”就认定为后台管理员账号。
- 支持管理员账号/密码维护；修复既有密码算法不兼容、数据库字段缺失等部署问题。

### UPLOAD-01 新短视频上传路径

- 后台短视频列表提供批量上传入口。
- 新短视频上传与旧图集流程区分，不能继续把新上传内容发布到旧图集。
- 用户指定过 EFV“新-短视频”作为新流程的分类标识。
- 本站后台新增分类需要能同步到云转码后台，并保存正确的关联关系。
- 待明确：新增远端分类之后，上传目标是按分类逐一映射，还是继续统一放在“新-短视频”；不要在两个策略间静默切换。

### UPLOAD-02 上传表单和限制

- 所属分类读取本站后台的短视频分类。
- 不要求管理员选择“上传者”，默认以管理员对应身份入库。
- 不需要“本组共用文字”字段。
- 可分批添加文件，最多 100 个视频。
- **单个视频最大 5 GB**，替代此前 45 MB；按当前实现口径为 5 × 1024³ 字节。
- 支持分片上传；浏览器、本地服务、代理及 EFV 接收端需要共同满足大文件限制。
- 上传进度条展示百分比和每个文件状态；区分“文件正在上传”与“后台正在提交 EFV”。
- 失败显示明确原因，支持重试失败文件；不能按钮无反应、无报错。

### UPLOAD-03 上传后入库与自动同步

- EFV 接受上传后，本站短视频表也必须存在对应记录，不能只有远端视频库或单独的上传记录页有数据。
- 记录关联所选本站分类、管理员上传身份、EFV 视频标识。
- 转码未完成时显示草稿/待同步等可理解状态，不伪装成已经可播放。
- 转码完成后自动获取 M3U8、清晰封面、时长和发布信息，并按本站发布规则展示。
- 手动同步可作为重试入口，不能成为每次上传后必须执行的步骤。
- 不同文件分别记录结果，不能一条成功就把整批都当成成功。
- 自动同步的具体运行周期尚无用户最终确认的数字，应在交付时明确告知，不能擅自写成每分钟一次。

## 9. EFV 采集、分类和媒体配置

### EFV-01 采集接口

- EFV `/admin/cmsapi` 是采集设置页，不是视频详情接口。
- 使用开启后的 `/api/provider/vod/?ac=detail` 采集分类和视频资料。
- 有采集 Key 时按远端要求传递；支持远端 IP 白名单限制。
- 可同步的信息包括视频标识、分类、标题、简介、播放线路、封面、截图、时长、更新时间，以及接口实际提供的标签、演员、导演等资料。
- 字段实际是否有值，以接口响应为准；接口不可用时应能区分配置未加载、鉴权失败和网络/分页问题。

### EFV-02 “国产短视频”同步到“国产”

- 将 EFV“国产短视频”分类同步到本站短视频“国产”分类。
- 同步新增和修改；远端删除或下架也应反映到本站。
- 用稳定的 EFV 视频标识识别同一条视频，不按标题相同判重。
- 报告接口总条数、实际读取数、不同视频 ID 数、重复数及新增/更新/下架结果。
- 分页重复、丢页或读取不完整时，不能直接执行差集下架。
- 数量不一致需解释统计口径，例如远端分类总数、采集接口可见数量和本站已发布数量的区别。
- 曾出现“读取 922 条、223 条重复、仅 699 个不同 ID”的反馈，属于待核查分页完整性的问题，不能把 922 条都当成 922 个不同视频。

### EFV-03 媒体域名配置

后台需要提供配置项，并写入配置文件：

```json
{
  "image_origin": "https://tupian.5cpic1.top",
  "m3u8_origin": "https://m3u8.5cvod1.top"
}
```

- 前台图片请求使用图片域名，视频播放请求使用 M3U8 域名。
- 保留媒体路径及必要参数，不用直接修改所有数据库记录来完成域名切换。
- 使用时读取当前配置；不能长期沿用数据库或旧缓存中的域名。
- 如果解密/鉴权使用本站中转地址，验收时还应核对其真正访问的上游域名，不能只看页面上的 `/efv-covers/...` 就认定配置失效或已经生效。
- 修改后既要验证已有内容，也要验证新上传内容。

### EFV-04 防盗链、防播放与图片加密

- 对接 EFV 时间戳、播放次数等防盗链功能，支持开启后的实际播放。
- 处理播放地址过期、403、分片/密钥获取失败，而不是只确认视频详情 API 返回成功。
- 按 EFV 官方说明解密封面和截图；可在浏览器生成 Blob URL 显示。
- 图片质量、域名配置、加密对接和播放鉴权分别验证，避免修复一种问题时破坏其他链路。
