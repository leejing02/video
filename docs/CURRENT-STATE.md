## 历史：2026-11-07 部署事故（已恢复）

- 经过：部署时使用了项目根目录的 `docker-compose.prod.yml`，且没有带 `--env-file`。www 先返回 404，随后 api 以 root、无密码连接数据库被拒（日志 `Access denied for user 'root' (using password: NO)`），api 反复重启，网站 502。
- 恢复：用 `deploy/docker-compose.prod.yml` + `deploy/docker-compose.source.yml`、`--env-file .env.prod` 重建 mysql 和 api，再重启 web（web 容器的 nginx 只在启动时解析 `api` 地址）。用户确认「都正常了」。
- 教训：只能用 `deploy/` 下的两个 compose 文件，并且必须带 `--env-file .env.prod`；不得使用根目录 `docker-compose.prod.yml`（没有 web 服务，缺 env 时数据库账号为空）。
- 待核对：数据库数据是否完整。两套 compose 使用同一数据卷 `video-prod_mysql_data`，推断数据仍在，但未逐表核对。
